# Checklist — before one outside person is given a login

**Reader:** the operator, and whoever is signing off the first pilot. Preconditions: you can read the
repo; for the verify commands you will also need the Render dashboard, the Neon account that owns the
live database, a `platform_admin` login and the `CRON_SECRET`, none of which this file contains.
**Written:** 2026-11-17, on branch `wave0/back-online`, from the tree and the existing runbooks.
**What this is not:** a procedure. Every how-to lives in a runbook and is linked, not restated:
[`render-deploy.md`](render-deploy.md) (hosting, keys, migrations, rollback),
[`email-delivery.md`](email-delivery.md), [`provision-a-database.md`](provision-a-database.md).

**How to read the State column.** Each state is what could be established from files and local commands
on 2026-11-17. Nothing here was checked against a running host, the live database, Render, Resend, Stripe
or GitHub: none is reachable or permitted from the authoring session. Where a state would need one of
those, it says `[UNVERIFIED]` or `[NEEDS DATA]`. A row is **DONE** only when its verify step has been run
and the output read. As of today: **0 of 38 rows are DONE.** Rows 2 and 10 are partly evidenced. Rows 1 to 25 were written first; rows 26 to 38 (section F) were added later the same day from findings made since, and `IN PROGRESS` there means a fix is being written on `wave0/back-online`, not that it is read, tested or gated.

**Rule for the whole list.** Per workspace `CLAUDE.md` §7.3, "set" and "configured" are not "works". A
variable being present is never the verify step.
